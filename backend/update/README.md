# Update log

One report per working day, named `YYYY-MM-DD.md`. Each report is a self-contained
end-of-day summary so anyone (including a fresh session) can pick up context without
re-reading the whole codebase.

Every report covers:

1. **What was done** — the concrete changes.
2. **Why** — the reasoning / decisions behind them.
3. **What each portion does now** — a current map of the code, component by component.
4. **Stubbed / deferred** — what exists as a placeholder and what's intentionally not built yet.
5. **Open items / next** — where to go from here.

Newest reports reflect the latest state; older ones are a historical trail of decisions.

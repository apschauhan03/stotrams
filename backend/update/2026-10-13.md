## 1. What was done

**Video (manual upload — no video generation yet)**
- Admin: a **🖼️ Photos / 🎬 Videos** toggle at the top of the panel (remembered per browser).
  Videos mode swaps the generation blocks for an **Upload a video** panel (MP4 / WebM / MOV,
  ≤100 MB, category + language, preview). Upload → `VIDEO` item in **To review**, then the
  usual approve → publish. Review tabs and counts are per type; "Publish now" counts both.
- Backend: `POST /admin/videos` (multipart) → `VideoUploadService`; stored under
  `videos/<category>/<date>/<uuid>.<ext>` through the same storage seam; served at
  `/videos/**` (`LocalMediaConfig`, Vite proxy). `GET /admin/candidates?type=IMAGE|VIDEO`.
  Videos skip the watermark at publish and in the startup backfill; prompt edits refuse
  videos. Multipart limit 100 MB (`MAX_UPLOAD_SIZE`), 413 with a readable message.
- No migration needed: `content_item.type` already allowed `VIDEO`.

**Master prompt: date, panchang, default prompt**
- **Date input** ("For date", default today IST) next to count/category.
- **Placeholders**: `{{TARGET_DATE}}` → `DD-MM-YYYY`, `{{NUMBER_OF_PROMPTS}}` → the count,
  per run only (saved text keeps them; case/spacing inside the braces don't matter).
- **`Panchang`** (new, pure Java): tithi at New Delhi sunrise, its end time, paksha, month
  (amanta + purnimanta, adhik detection), Navratri day + Navadurga form, Vikram Samvat,
  sunrise/sunset. Meeus low-precision Sun/Moon (≈0.01°), Lahiri ayanamsa, NOAA sunrise.
  Verified against published panchangs: Pratipada 10 Oct 21:19 → 11 Oct 21:31 IST (ref
  21:19 → 21:30); Amavasya ends 9 Nov 12:31 (ref 12:33); Delhi sunrise/sunset correct across
  seasons; VS 2083 from Chaitra Navratri 2026.
- **`CalendarLookup`** (new): independent web check via OpenAI Responses API + `web_search`,
  strict schema (tithi as 1–30, month from an enum) so comparing needs no fuzzy spelling.
  Optional per run ("Also check the panchang on the web", ~1–3¢), `PROMPT_WEB_SEARCH` to
  disable.
- **`DateContext`** (new): builds what the writer is told (weekday + Hindi vaar, computed
  panchang, web festivals and sources, disagreement note) and the `CalendarCheck` the
  admin sees. Tested on 20 Oct 2026: computed and web agree (Shukla Navami, Ashwin), web
  found Maha Navami / Saraswati Visarjan with 3 sources.
- Admin UI: **two separate boxes**, "Computed on the server" and "Found on the web", with
  ✓ / ⚠ on tithi and month, festivals, source links; red banner on disagreement.
- **Default master prompt** = the user's full "Hindu Calendar-Based Devotional Image Prompt
  Generator" (`resources/prompts/master-prompt.txt`, ~17 k chars). Used when nothing is
  saved; "↺ Reset to default master prompt" (`DELETE /admin/principle`) brings it back.
  Limit raised 8 k → 30 k. The previously saved short prompt was reset to it.
- `PromptWriter` reply schema widened: `research_summary`, per-prompt `negative_prompt`,
  `recommendation`. Summary + recommendation shown above the drafts; the negative prompt is
  appended as "Avoid: …" (gpt-image has no negative-prompt input). Word cap 120 → up to 350
  when the principle asks for detail; read timeout 3 → 8 min.
- House-rule fixes found by test runs: no "no text" when the principle asks for Hindi text;

  festival (one run had called Navratri day 4 "Ganesh Chaturthi"); Navratri day names the
  goddess.
- **Blocks remember their date** (V8 `prompt_template.target_date`): set from the master
  prompt's date on bulk create, editable in the block editor, shown as a 📅 chip.

## 2. Why

- **Manual video upload first**: OpenAI's Sora API was shut down (24 Sep 2026), so video
  generation needs a new vendor; uploading by hand gets the whole video path (storage,
  review, publish, playback, sharing) working before any money is spent on generation.
- **Compute the panchang instead of asking the model**: the text API has no web access and
  tithi dates move every year; the model guessed confidently. The calculation is free,
  exact to minutes, and repeatable. The web check is kept *independent* (it never sees the
  computed answer) so agreement means something.
- **Strict enums for the web answer**: comparing "Ashvin / Ashwina / Ashwin" by string
  would produce false alarms.
- **Default prompt in a file**: it's long, versioned with the code, and "reset" is just
  forgetting the saved copy.
- **Reels layout band**: the product's images carry the blessing text at the bottom; a
  full-bleed reel with controls on top hid exactly that.

## 3. What each portion does now

- `service/VideoUploadService` — validates and stores an uploaded video, creates the
  `VIDEO` candidate.
- `service/prompting/Panchang` — the astronomy: `forDate(date)` → `Day` (tithi, end, paksha,
  months, adhik, samvat, sunrise/sunset, Navratri); `describe()` is the writer's paragraph.
- `service/prompting/CalendarLookup` — one web-search call per run, strict JSON.
- `service/prompting/DateContext` — combines both into the writer's context + `CalendarCheck`.
- `service/prompting/PromptWriter` — returns `Result(drafts, researchSummary, recommendation)`.
- `controller/PrincipleController` — GET (saved or default) / PUT / DELETE (reset) / write
  (placeholders → date context → writer).
- `controller/PanchangController` — public `/api/panchang`.
- `controller/AdminController` — candidates by type, `POST /admin/videos`.
- Frontend: `pages/PanchangPage`, `components/PanchangCard`, `components/BottomNav`,
  `components/ReelViewer`, `pages/admin/VideoUploadPanel`; `PrincipleSection` (date, web
  check, calendar boxes, summary/recommendation, reset); `BlocksPanel` (date chip/field).

## 4. Stubbed / deferred

- **No video generation** (Sora gone). Architecture + cost estimate discussed: fal.ai /
  Kling / Seedance / Veo behind a `VideoGenerator` seam with a DB job table and poller;
  ~$15–40/month at 2 animated images a day.
- **Videos aren't watermarked** (needs ffmpeg on the server); upload them pre-branded.
- Panchang is for **New Delhi only**; no nakshatra / yoga / karana; festivals are not
  computed (only Navratri / Ekadashi / Purnima / Amavasya highlights).
- On a computed-vs-web **disagreement**, the web's festivals are still passed to the writer
  (could mix e.g. "Maha Navami" with an Ashtami tithi). Proposed fix below.
- The two calendar boxes and the reset button were checked through the API, not visually
  with a real paid run in the browser.
- **Real WhatsApp sharing** still untested on a phone: needs HTTPS (or the Android Chrome
  insecure-origin flag); the HTTPS tunnel attempt was blocked by the permission system.

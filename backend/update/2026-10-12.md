  Tiro Devanagari Hindi for स्तोत्रम्, lotus redrawn as SVG (favicon, `lotus.svg`, component).

**Backend**
- **Admin login** — Spring Security session login by email; admin account from
  `ADMIN_EMAIL`/`ADMIN_PASSWORD` (bcrypt row upserted at startup); login rate limit; all
  `/admin/**` 401 without a session.
- **Generation blocks** (V4) — `prompt_template` rows managed from the panel: name,
  category, language, prompt, model (dropdown of real models), images per run, active.
  Generate one block or all active (≤200 images per click). Refuses up front when a
  provider can't run (e.g. no OpenAI key) instead of failing silently in the background.
- **Principle prompt** (V5) — saved master instruction; `PromptWriter` (OpenAI
  `gpt-5.4-mini`, strict JSON schema) drafts N distinct prompts; admin edits, then
  bulk-creates blocks.
- **Publishing** (V3) — "Publish now" + daily auto-publish (cron in DB, editable from the
  panel, default 05:00 IST, re-registered live). Approve and publish are separate steps;
  rejecting a live item takes it down.
- **Watermark** (V6) — every published image stamped with lotus + स्तोत्रम् **top-right**,
  re-encoded as ~450 KB JPEG (was 2.8 MB PNG); clean original kept; versioned so a design
  change re-renders all live images with new URLs. Startup backfill stamped the 10 live
  images.
- **Prompt-based editing** (V7) — edit any image with an instruction (OpenAI
  `/images/edits`); result is a new candidate linked to its source; model selectable,
  default gpt-image-1-mini.
- **Fixes:** images generated after server start were 404 (Spring served the build copy of
  `static/`) → `LocalMediaConfig` serves from disk; feed no longer filters by language
  (images are shared across languages); `ApiErrorHandler` returns readable `{message}`s.

**Secrets / repo hygiene**
- OpenAI key moved out of `application.yml` into gitignored
  `backend/src/main/resources/application-local.yml` (imported optionally; excluded from
  the jar by `maven-jar-plugin`).
- `.githooks/pre-commit` and `pre-push` block local-secret files and key-shaped strings
  (push hook fails closed). Enabled with `git config core.hooksPath .githooks`. Git history
  scanned: no key was ever committed.

## 2. Why (decisions & reasoning)

- **Watermark in code, not in the prompt** — image models misspell Devanagari and place text
  inconsistently; stamping at publish is the only way to *guarantee* it. Done at publish
  (not generation) so review sees clean images and originals stay re-editable.
- **No publish without the mark** — an item that fails watermarking stays APPROVED.
- **Versioned watermark path** — re-rendering under the same URL would leave 30-day browser
  caches (and later the CDN) serving the old design.
- **Approve ≠ publish** — the admin wanted a scheduled job and a manual button; keeping
  APPROVED as a queue makes both trivial and reviewable.
- **Edits create a new candidate** — never destroy the original; compare, then choose.
  Per attempt an edit costs about the same as a generation; it saves money by needing fewer
  attempts. The mini model is cheap but redrew faces and dropped Shiva's snake in a real
  test — use gpt-image-2 when iconography must be preserved.
- **Principle drafts are reviewed before becoming blocks** — a bad prompt wastes paid runs.
- **One image per OpenAI call** (`n: 1`), in parallel — same cost as `n: 2`, but one failure
  doesn't lose the rest and images land as they finish.
- **Login by email, admin from env vars** — the repo is public; no credentials or hashes in
  migrations.
- **CSRF via SameSite=Strict session cookie** rather than tokens — JSON API, no CORS.
- **Demo mode in the frontend** — the UI is usable and testable with the backend down.
